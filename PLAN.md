## 0. Где мы сейчас

### Сделано (v1)
- Статический сайт на `<model-viewer>` 4.4.0: каталог из 4 предметов, по 4 цвета. **Один GLB на каждый цвет**, цвет запечён в текстуру или материал.
- AR: Android — Scene Viewer, при неудаче WebXR; iPhone — Quick Look, USDZ model-viewer собирает сам. На компьютере вместо кнопки QR-код. Есть подсказки, если AR недоступен.
- Сборка: скрипты в `scripts/`. Проверки: вес ≤ 3 МБ (`check-sizes`) и **glTF-валидатор Khronos без ошибок** (`validate-models`, добавлен после теста).

### Результаты теста на Android (Chrome, WebXR) и что исправлено

| Проблема | Причина | Исправление (уже на Pages) |
|---|---|---|
| ✅ Цвета в AR совпадают, загрузка быстрая | — | — |
| ❌ Кресло то маленькое, то большое | `ar-scale="fixed"` уже стоял. Но в WebXR model-viewer до постановки показывает предмет «в воздухе» на расстоянии, чтобы он целиком влез в кадр. Пока поверхность не найдена, размер на глаз «прыгает». После постановки масштаб 1:1, щипок отключён | Первым запускается **Scene Viewer** (масштаб 1:1, параметр `resizable=false`, своя сетка и тень). `ar-scale="fixed"` выставляется ещё и из кода для каждого предмета |
| ❌ Торшер: непонятно, встал ли, косит, улетает | WebXR без индикатора поверхности; высокий тонкий предмет сильнее показывает дрожание трекинга | Scene Viewer первым для всех предметов. В WebXR (запасной режим): до постановки — подсказка «Поводите телефоном над полом» с анимацией, после — зелёный статус «Стоит на полу · перетащите, чтобы сдвинуть», при потере трекинга — «Поверхность потеряна». Контактная тень стала чётче (`shadow-softness` 0.8 → 0.35) |
| ❌ Настольная лампа не открывается в AR | **Ошибка в модели.** В лампах были нормали нулевой длины: точки профиля на оси вращения давали вырожденные треугольники. glTF-валидатор: 6 ошибок `ACCESSOR_VECTOR3_NON_UNIT` на модель. Лампа единственная запускалась через Scene Viewer, а он не открывает модели с ошибками валидации. Торшер с той же ошибкой открывался, потому что WebXR к ней терпим | Нормали исправлены, все 16 моделей проходят валидатор с 0 ошибок. Валидатор встроен в сборку: модель с ошибками не соберётся |

**Второй тест (Android):** Scene Viewer не стартует — Chrome на секунду начинает переход и возвращается. Вероятно, нет или отключено приложение Google. Поэтому:
- **Основной режим на Android — собственный WebXR** (`js/xr-ar.js`, на основе примера three.js `webxr_ar_hittest`, MIT):
  - кольцо-указатель размером с основание предмета — только на горизонтальных поверхностях (hit-test по плоскостям);
  - предмет появляется только после касания и стоит ровно (наклон поверхности игнорируется);
  - после постановки фиксируется: WebXR Anchors, если телефон их поддерживает; за hit-test больше не следует;
  - масштаб 1:1, контактная тень, поворот одним пальцем, «Переставить», подсказки.
- Запасной путь: `ar-modes="webxr scene-viewer quick-look"` в model-viewer.
- Отладка `?debug=1`: ar-status, canActivateAR, выбранный режим, журнал, строка состояния hit-test внутри AR.
- model-viewer подключён модульной сборкой: одна копия three.js на страницу.

Встроенный WebXR model-viewer рисовать кольцо и ставить предмет по касанию не умеет, поэтому этот режим написан отдельно. В Chrome на компьютере проверены загрузка модуля, рендер моделей в three.js (размеры 1:1, тень, кольцо) и вёрстка оверлея. **Сама AR-сессия проверяется только на телефоне.**

## 1. Новая задача в двух словах

Модели загружает **магазин**, а не покупатель:

```
3D-дизайнер ──MODEL-SPEC.md──► GLB ──► Админка (браузер, без сервера)
                                         │ проверка → исправление → превью
                                         ▼
                        ZIP: catalog.json + models/<товар>/<вариант>.glb + posters/
                                         │ распаковать в репозиторий / загрузить на GitHub
                                         ▼
Покупатель: каталог → карточка → вариант → «Посмотреть в комнате» (QR на компьютере)
```

## 2. `catalog.json` + папка `models/` (пункт 1)

Сайт перестаёт брать данные из `js/catalog.js` и читает `catalog.json` через `fetch`. Остальная логика карточки не меняется.

```json
{
  "version": 1,
  "currency": "RUB",
  "items": [
    {
      "id": "chair-mira",
      "name": "Кресло «Мира»",
      "price": 34900,
      "category": "floor",
      "size_cm": { "w": 85, "d": 77, "h": 107 },
      "description": "…",
      "poster": "posters/chair-mira.webp",
      "variants": [
        { "id": "linen-grey", "name": "Светло-серый лён", "swatch": "#bdb7ac",
          "model": "models/chair-mira/linen-grey.glb" },
        { "id": "emerald", "name": "Изумруд", "swatch": "#2f6b55",
          "model": "models/chair-mira/emerald.glb" }
      ],
      "source": { "file": "chair-mira.glb", "variants_ext": true, "added": "2026-11-12" }
    }
  ]
}
```

| Поле | Как используется |
|---|---|
| `category` | `floor` → `ar-placement="floor"`, подсказка «над полом»; `table` → тоже `floor` (у model-viewer «пол» = любая горизонтальная поверхность), подсказка «над столом»; `wall` → `ar-placement="wall"`, у Scene Viewer `enable_vertical_placement` |
| `size_cm` | Админка заполняет по габаритам модели, магазин может поправить для подписи. В AR всегда идёт масштаб из модели 1:1 |
| `variants[].model` | **Отдельный GLB на вариант — обязательно**, даже если дизайнер прислал один файл с `KHR_materials_variants`. Причина: Scene Viewer получает только ссылку на файл и всегда показывает материал по умолчанию — параметра «вариант» у него нет (документация Scene Viewer + код model-viewer). Админка сама нарежет файл с вариантами на отдельные GLB |
| `swatch` | Цвет кружка. Админка предлагает его автоматически: средний цвет основной текстуры варианта |

## 3. Админка `admin.html` (пункт 2): только браузер, без сервера

Файлы никуда не загружаются: всё обрабатывается на компьютере менеджера. Основа — glTF-Transform в браузере (`WebIO`) и валидатор Khronos.

### 3.1 Шаги экрана

1. **Загрузить GLB** перетаскиванием или кнопкой. Можно загрузить и текущий `catalog.json` — он подтянется с сайта автоматически.
2. **Проверка** — таблица «✓ / ⚠ / ✗» с кнопками «Исправить»:

| Проверка | Правило | Авто-исправление |
|---|---|---|
| Валидность | glTF-Validator: **0 ошибок** (иначе Scene Viewer не откроет) | — (покажем, что не так) |
| Вес | ⚠ > 10 МБ, ✗ > 15 МБ (порог валидатора Scene Viewer) | Текстуры → ≤ 2048 px JPEG (PNG, если есть прозрачность); `dedup`, `prune`, `weld`; упрощение сетки |
| Полигоны | ⚠ > 100 000 треугольников (рекомендация Scene Viewer: 30–50 тыс.) | `simplify` (упрощение meshoptimizer, без расширений сжатия) |
| **Реальный масштаб** | Габариты в см и сравнение с типовыми для категории: диван 150–300 см, стол 40–200, лампа 20–200. ✗ если < 5 см или > 5 м (диван «3 мм» или «30 м») | Кнопки «Модель в см → ×0.01», «в мм → ×0.001», «в дюймах → ×0.0254» и ввод известной высоты |
| Точка опоры | Низ модели на y = 0, центр по X/Z | `center({pivot:'below'})` |
| Ориентация | Y вверх, «лицом» к +Z — проверяет менеджер по превью | Кнопки «Повернуть 90°» |
| Варианты | `KHR_materials_variants`: список имён | Нарезка на отдельные GLB, вариант становится материалом по умолчанию |
| Нет вариантов | Предложить «Добавить цвета вручную» | Для материалов без текстуры — смена цвета. Для текстурных — перекраска текстуры на canvas (алгоритм из `build-models.mjs`: замена оттенка с сохранением фактуры), иначе цвет не дойдёт до Quick Look |
| Расширения | ✗ `EXT_meshopt_compression`, `KHR_texture_basisu` (KTX2), `EXT_texture_webp` | Распаковать и пересохранить без них (Scene Viewer их не открывает, KTX2 ломает USDZ) |
| USDZ (iPhone) | Пробная сборка USDZ тем же экспортёром, что у model-viewer | При ошибке — объяснение. Опционально — сохранить `.usdz` в ZIP (п. 4) |

3. **Превью** в `<model-viewer>` с переключением вариантов. Рядом габаритная коробка с размерами и силуэт человека 175 см для масштаба.
4. **Карточка товара:** название, цена, категория, описание, названия и цвета вариантов.
5. **«Добавить в каталог»** — скачивается ZIP:
   - `catalog.json` (обновлённый);
   - `models/<id>/<вариант>.glb`, `posters/<id>.webp` (кадр из model-viewer);
   - `КАК-ОПУБЛИКОВАТЬ.txt`.

   Плюс отдельная кнопка «Скачать только catalog.json» — для правки цен и названий без моделей.
6. **Инструкция публикации** (без git): GitHub → репозиторий → **Add file → Upload files** → перетащить содержимое ZIP → Commit. Pages обновится примерно за минуту. Альтернатива для тех, кто с git: распаковать в папку проекта, затем `git add`, `git commit`, `git push`.

Также в админке: список товаров из `catalog.json` с кнопками «Удалить» и «Изменить цену/название» (тоже скачивание JSON).

### 3.2 Про «сжатие meshopt» — важно

Расширение `EXT_meshopt_compression` в итоговых файлах **не используем**: Scene Viewer такие модели не открывает. Кроме того, decoder для model-viewer по умолчанию выключен и тянется с jsDelivr.

Из meshoptimizer берём **упрощение сетки (simplifier)**: оно уменьшает число треугольников, а файл остаётся обычным GLB. Вес снижаем текстурами (≤ 2048 px, JPEG) и чисткой. Это совместимо со всеми тремя режимами AR.

Draco (`KHR_draco_mesh_compression`) Scene Viewer, вероятно, поддерживает (его движок Filament умеет), но в документации Scene Viewer это не указано **[не проверено]** — оставляем выключенным до теста на устройствах.

## 4. iPhone и USDZ (пункт 3)

| Вопрос | Ответ | Насколько точно |
|---|---|---|
| model-viewer сам делает USDZ из GLB? | Да, если не указан `ios-src`. В момент нажатия он экспортирует **текущую сцену** через three.js `USDZExporter`, к ссылке добавляется `#allowsContentScaling=0` при `ar-scale="fixed"` | Код model-viewer 4.4.0. Сборка проверена на всех 16 вариантах в Chrome (кресло ~5.5 МБ, стол ~3.5 МБ) |
| Сохраняется ли вариант цвета в Quick Look? | **Да, если цвет в текстуре или в материале без текстуры.** **Нет**, если цвет — оттенок, умноженный на текстуру (документация model-viewer, пример Scene Graph). Наши файлы на вариант запечены, значит должно работать | **[не проверено на iPhone]** — вы пока тестировали только Android |
| `KHR_materials_variants` + Quick Look | Экспортируется текущая сцена, значит выбранный вариант попадёт в USDZ (при запечённых текстурах). Но для Scene Viewer всё равно нужны отдельные файлы — поэтому оставляем один GLB на вариант для всех режимов | Код |
| Подводные камни | KTX2-текстуры ломают сборку USDZ (model-viewer не вызывает `setTextureUtils`). Большие текстуры → долгая сборка на телефоне | Код. Админка не пропустит KTX2, `ar-usdz-max-texture-size="2048"` |

**Решение:** USDZ по умолчанию не храним. Если тест на iPhone покажет расхождение цвета или долгую сборку (> 3–4 с), админка начнёт собирать `.usdz` на каждый вариант тем же экспортёром прямо в браузере. Файлы положим в ZIP и подключим через `ios-src`; в `catalog.json` у варианта появится поле `"usdz"`.

Это ускорит запуск на iPhone, но не исправит модель, которую экспортёр не умеет переносить. Поэтому главное условие — запечённые цвета, и оно прописано в MODEL-SPEC.

## 7. Боевая версия: подключение к CMS (пункт 6)

### 7.1 Общая схема
- В карточке товара CMS — поле или свойство «3D-модель» (ссылка на GLB) или набор ссылок по вариантам (торговым предложениям).
- На странице товара — наш виджет `ar-viewer.js`: карточка из прототипа, вынесенная в отдельный модуль. Он рисует `<model-viewer>`, кнопки вариантов, AR-кнопку и QR по `data`-атрибутам.
- **Модели лежат на домене магазина или в его CDN / S3** (https, CORS для `<model-viewer>`, публичная ссылка для Scene Viewer), а не на github.io.
- Админка в боевой версии вместо скачивания ZIP загружает файлы в медиатеку CMS или в S3 через API CMS. Для этого нужен сервер или плагин.

**Не берём:**
- glTF Report (gltf.report): «open core, not open source», исходники интерфейса закрыты. Можно только давать ссылку менеджерам как внешний инструмент.
- `mikktspace` (npm): последний релиз 2022 года.
- usd_from_gltf: заброшен с 2020 года.
- Модули Битрикса с маркетплейса: закрытый код.

**Пишем сами:**
- `admin.html` с логикой шагов и правил проверки (~600–800 строк). Отдельные операции берём из glTF-Transform, свои — только сценарий и интерфейс.
- Перекраска текстуры на canvas (перенос алгоритма из `build-models.mjs`).
- Сборка ZIP и инструкции.
- Переход сайта на `catalog.json`.
- `ar-viewer.js` — для боевой версии, позже.

## 10. Этапы после «да»

1. **Сайт на `catalog.json`:** перенос текущих 4 товаров, цена, фильтр категорий. Сайт выглядит так же.
2. **Админка, чтение:** загрузка GLB, все проверки и превью.
3. **Админка, исправления:** масштаб, опора, текстуры, упрощение, нарезка вариантов, ручные цвета.
4. **Админка, выгрузка:** ZIP + `catalog.json` + инструкция. Проверяю на моделях с Poly Haven, в том числе специально «сломанных»: в мм, в см, с meshopt, с KTX2, с вариантами.
5. **iPhone:** по вашему тесту решаем про готовые USDZ (§4).
6. Публикация на Pages — после вашего «да».

## 11. Чек-лист перепроверки текущей версии (после исправлений)

**Android (Chrome):**
- [ ] Кресло, стол, торшер, лампа: нажатие → открывается **приложение Google для AR (Scene Viewer)**, а не полноэкранный режим в браузере
- [ ] В Scene Viewer предмет стоит на полу, щипок **не** меняет размер. Кресло ~85 см в ширину, торшер ~160 см в высоту — сверить рулеткой
- [ ] Настольная лампа: навести на стол, дождаться сетки на столешнице — лампа встаёт на стол
- [ ] Цвет в AR совпадает с выбранным (проверить 2 цвета на каждом предмете)
- [ ] Если Scene Viewer не открылся — на странице появилось сообщение. Повторное нажатие открывает AR в браузере: видна подсказка «Поводите телефоном над полом», после постановки — зелёный статус «Стоит на полу»
- [ ] Выход из AR возвращает в ту же карточку

- [ ] Quick Look открывается для всех 4 предметов, предмет на полу (лампа — на столе), щипок не масштабирует
